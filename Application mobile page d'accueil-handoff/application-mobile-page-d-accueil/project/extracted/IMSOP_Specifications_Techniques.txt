5. Règles critiques
Règle 1
L&apos;administrateur informatique ne doit pas disposer automatiquement d&apos;un accès au contenu médical.
Règle 2
Un spécialiste ne voit que les dossiers qui lui sont attribués.
Règle 3
Un assureur ne doit accéder qu&apos;aux informations nécessaires à la gestion de la prise en charge.
Règle 4
Le patient conserve la maîtrise des autorisations de transmission de ses données, sous réserve des obligations légales applicables.
Règle 5
Toute consultation d&apos;un dossier médical doit être enregistrée dans l&apos;audit trail.

DOCUMENT 7 — Cybersécurité et protection des données
1. Objectif
La sécurité doit être considérée comme une fonction critique du projet. Les données médicales étant particulièrement sensibles, le système devra appliquer :
Privacy by Design et Security by Design.
2. Authentification
MFA ;
OTP ;
gestion des sessions ;
politique de mot de passe ;
détection des connexions inhabituelles ;
verrouillage après tentatives excessives.
3. Chiffrement
chiffrement TLS pour les communications ;
chiffrement des données sensibles ;
chiffrement du stockage documentaire ;
gestion sécurisée des clés.
4. Contrôle d&apos;accès
Application du principe :
Least Privilege — chaque utilisateur reçoit uniquement les droits nécessaires.
5. Audit
Enregistrer :
connexion ;
consultation ;
téléchargement ;
modification ;
transmission ;
suppression ;
validation.
6. Protection documentaire
Chaque fichier doit être :
contrôlé ;
analysé antivirus ;
stocké de manière sécurisée ;
associé à un dossier ;
soumis aux droits d&apos;accès.
7. Sauvegardes

stockage redondant ;
sauvegarde hors environnement principal ;
tests de restauration.
8. Plan de reprise
Définir :

responsables ;
procédure de communication de crise.
9. Tests
Avant mise en production :

tests d&apos;accès ;
tests d&apos;intrusion ;
